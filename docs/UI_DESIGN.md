# ModelBridge 界面设计说明

本文记录 ModelBridge 界面的设计目标与验收约束，供后续维护使用。界面面向 API 新手，强调清楚的操作路径、可理解的连接诊断和稳定的本地聊天体验；修改界面时应保留现有核心功能。

## 产品背景

- 产品名称：ModelBridge
- 定位：本地运行、支持多家 OpenAI-compatible API 的聊天客户端
- 主要用户：第一次接触 API 的普通用户，以及需要切换多个模型平台的开发者
- 关键价值：密钥留在本机、平台切换简单、连接问题能被解释、聊天记录可管理
- 技术约束：原生 HTML、CSS、JavaScript；不增加前端框架、图标库、网络字体或远程图片

## 设计目标

1. 用户打开页面后，3 秒内能看懂当前平台、模型、连接状态和下一步操作。
2. 把“开始聊天”设为最强主任务；平台、能力、用量等工具保持易找，但不抢注意力。
3. 建立安静、可信、带一点编辑工作室气质的品牌感，避免通用后台模板和过度炫技。
4. 桌面端要像完整工作空间，手机端要像真正可用的聊天产品，不能只是缩小桌面布局。
5. 所有状态都要可感知：未配置、加载、成功、失败、禁用、正在生成、检测连接和空记录。

## 视觉方向

- 关键词：温和、专注、可信、纸张质感、现代工具感、低噪声。
- 主色使用深森林绿，背景使用暖白与浅灰绿；琥珀色只表达提醒，红色只表达错误或危险。
- 使用细边框、柔和阴影、清晰留白和轻微层次，不使用大面积高饱和渐变。
- 用统一的圆角、间距、字号和交互状态建立秩序。正文保证舒适阅读，辅助文字仍需清晰可辨。
- 品牌图形使用 CSS 和文字完成，不依赖外部素材。

## 重点界面

### 1. 侧栏

- 品牌区更有辨识度，并明确“本地运行”的安全感。
- “开始新对话”保持最高优先级。
- 对话记录与模型选择使用清楚的分段导航；空状态需要告诉用户内容何时出现。
- 当前对话、悬停、键盘焦点、危险操作必须容易区分。

### 2. 顶栏

- 平台与模型是主要上下文，可点击切换。
- 连接状态显示为简洁状态胶囊。
- 用量、模型能力、平台设置组成统一的次级工具组，视觉重量低于聊天任务。

### 3. 欢迎页

- 展现一句明确主标题、一句用途说明和本地隐私提示。
- 提供 3 个高质量起始任务，点击后只填入输入框，由用户确认后发送。
- 页面需要有品牌氛围，但保留足够安静空间，让输入框自然成为最终落点。

### 4. 对话与输入区

- 用户消息和 AI 回复必须能快速扫视区分；AI 长文本保持优秀的阅读宽度和行高。
- 输入区像稳定的浮动工作台：显示发送目标、附件入口、键盘提示和发送/停止状态。
- 在窄屏上减少次要说明，保证输入框、发送按钮和安全区域始终可用。

### 5. 平台接入向导

- 延续“选择平台 → 粘贴密钥 → 开始使用”的三步心智模型。
- 当前步骤、已完成步骤和下一操作要明显；技术细节默认收起。
- 检测进度、取消、失败原因和重试入口必须在当前视线范围内。

## 交互与无障碍要求

- 所有交互元素有明显的 hover、active、disabled 和 `:focus-visible` 状态。
- 保持语义化标签、对话框焦点陷阱、Esc 关闭、移动侧栏遮罩和键盘导航。
- 动画只用于说明状态变化，尊重 `prefers-reduced-motion`。
- 正文与辅助文字保持足够对比度；触控目标尽量不小于 40px。
- 不改变现有 DOM ID、接口协议、数据存储方式和安全边界。

## 实施与验收

- 优先通过设计变量和可复用组件样式统一界面，减少零散覆盖。
- 同时检查 1440×1000 桌面端和 390×844 手机端。
- 验收首屏、已有对话、模型切换、平台向导、连接检测、失败重试和键盘焦点。
- 不使用真实 API Key；浏览器验收只调用模拟 API。
- 最终交付可运行代码、桌面/手机截图、语法检查和自动化测试结果。
